# WP-CLI імпортери

Три незалежні імпортери, всі командного рядка (`@when after_wp_load`), без cron — запускаються вручну коли потрібно.

| Команда | Джерело | Що пише |
|---|---|---|
| `wp nbu parse-souvenir` | bank.gov.ua | CPT `coins` (самі монети, картинки, дизайнери) |
| `wp uacoins import-prices` | ua-coins.info | таблиця `{prefix}coin_prices`, `source=ua-coins.info` (щоденна історія цін) |
| `wp nbuarchive import-prices` | coins.bank.gov.ua (архів магазину НБУ) | таблиця `{prefix}coin_prices`, `source=coins.bank.gov.ua` (одна "остання відома" ціна) |

Цей файл — про обидва цінові.

**ua-coins.info має ще один імпортер — окремий Node-сервіс `node-coins-price-parser`** (не в цьому репо, пише в ту саму БД напряму через `mysql2`, без участі WordPress). Він з'явився в migration phase 5 і покриває те саме джерело тим самим алгоритмом матчингу (навіть той самий `--min-score=55` — `similar_text()` там побайтовий порт PHP-версії). `wp uacoins import-prices` лишається робочим — обидва інструменти пишуть в одну таблицю й діляться кешем матчів (постмета `_uacoins_id`/`_uacoins_slug`/`_uacoins_match_score` на `coins`-постах), тож який запускати — байдуже.

---

## Джерело 1: ua-coins.info (`wp uacoins import-prices`)

Публічний каталог, окремий сайт, ніяк з нами не пов'язаний. Даних напряму через офіційний API немає, тому пайплайн — по суті контрольований скрапінг двох публічних сторінок на кожну монету:

1. **Сторінка пошуку** `GET /ua/search?search=<назва>` — HTML зі списком монет-кандидатів (назва + `/ua/list/{id}-{slug}`).
2. **Сторінка монети** `GET /ua/list/{id}-{slug}` — в атрибуті `data-prices-url` на цій сторінці сервер щоразу генерує нове підписане посилання виду `/coin/prices/{id}?_hash=...&expires=...`. Хеш неможливо порахувати самостійно — він видається лише разом зі сторінкою, тому крок 2 обов'язковий перед кожним зверненням до цін (кешувати підписане посилання надовго не можна, воно короткоживуче).
3. **Ціновий ендпоінт** `GET /coin/prices/{id}?_hash=...&expires=...` — віддає JSON: `[{"date": "YYYY-MM-DD", "price": 201}, ...]`.

### Дві речі, які виявились тільки емпірично (не видно з самого API)

- **Крок 3 повертає 403**, навіть з дійсним `_hash`, якщо запит не має `Referer` на сторінку монети (крок 2) і не виглядає як браузер (`User-Agent`). Класичний anti-hotlink захист, не пов'язаний з підписом самого посилання.
- **Рейт-ліміт**: сайт віддає `429` вже після 2-3 швидких запитів поспіль, з заголовком `Retry-After` (зазвичай `5`). Команда це враховує — є вбудований backoff-retry (`http_get()`), тому саму команду можна просто запускати без зовнішнього троттлінгу.

### Як зіставляємо монету з ua-coins.info

Ручного мапінгу ID немає — матчинг автоматичний, за схожістю назви:

1. Беремо `post_title` нашої монети (CPT `coins`), декодуємо HTML-ентіті, чистимо (`clean_search_query()`): прибираємо бектики/фігурні лапки й кінцеву позначку металу в дужках (`(с)`, `(н)`, `(c)` — і кирилична, і латинська `c` трапляються в реальних даних).
2. Шукаємо цю очищену назву на ua-coins.info (`/ua/search`), парсимо кандидатів **лише з основного контенту сторінки** (`#main-content-block`) — інакше в матчі потрапляють випадкові посилання з бічних віджетів (наприклад, "Останні коментарі").
3. Для кожного кандидата рахуємо `similar_text()` між нормалізованими (lowercase, без пунктуації) назвами, беремо найкращий збіг.
4. Якщо найкращий score ≥ порогу (`--min-score`, за замовчуванням **55**) — приймаємо матч і **кешуємо** `ua-coins.info id` в `_uacoins_id` / `_uacoins_slug` / `_uacoins_match_score` (постмета нашого поста `coins`). Наступні запуски беруть матч з кешу й не роблять пошук повторно — доки не передати `--rematch`.

**Відомі промахи матчингу** (не баг, очікувана поведінка):
- "Ролик обігових пам'ятних монет ... (у ролику 25 монет)" і набори — на ua-coins.info немає окремих сторінок для упаковок з 25 монет, там каталогізовані одиничні монети.
- Деякі щойно випущені монети можуть ще не з'явитись на ua-coins.info взагалі.

## Джерело 2: coins.bank.gov.ua — архів магазину НБУ (`wp nbuarchive import-prices`)

Офіційний онлайн-магазин НБУ, розділ "Архів" (`/arhiv/c-457.html`, ~350 позицій, пагінація `?page=N`). На відміну від ua-coins.info, тут **не історія цін по днях, а одна ціна** — сторінка кожного товару прямо каже: *"Вартість продукції вказана станом на дату останньої реалізації"*. Тобто це радше "остання офіційна ціна продажу", ніж time series.

### Чому немає HTTP-скрапінгу, як для ua-coins.info

Сайт захищений **Bunny Shield** — JS proof-of-work anti-bot челендж (виконується в браузері, частково через WASM), схожий класом на Cloudflare Challenge. `wp_remote_get`/`curl` без виконання JS отримують сторінку-заглушку "Establishing a secure connection..." замість контенту. Ми свідомо **не реалізовуємо обхід** цього челенджу в PHP (це вже було б обходом чужого anti-bot захисту, а не скрапінгом публічного API, як у випадку ua-coins.info).

**Робочий процес замість цього — напівручний:**
1. Дані з `/arhiv/c-457.html?page=N` збираються через реальний браузер (Claude в Chrome або людина) — назва товару + ціна + артикул з кожної сторінки архіву.
2. Зібране складається в JSON: `[{"title": "...", "price": 458, "sku": "8GT"}, ...]`.
3. `wp nbuarchive import-prices --file=<шлях-до-json>` матчить і пише в БД.

### Як зіставляємо монету

На відміну від ua-coins.info (де матчимо проти чужого пошуку), тут матчимо **вхідні title з дампу проти вже наявних `coins`-постів у нашій БД** — усі публікаційні монети завантажуються одним запитом (`load_coins()`), далі порівняння в пам'яті через `similar_text()` (та сама нормалізація — `clean_title()`/`normalize_title()`, дублює логіку `FetchUaCoinsPricesCommand`, спільного класу немає, обидва командні класи самодостатні за конвенцією цього каталогу).

**Поріг за замовчуванням тут значно вищий — `--min-score=85`** (проти 55 для ua-coins.info). Причина: у каталозі багато шаблонних назв на кшталт `Ролик обігових пам'ятних монет "X" (у ролику 25 монет)`, які відрізняються лише вставкою `X` (назва області/об'єкта) — при порозі 55-60 такі назви хибно матчаться одна на одну (перевірено: "Антонівський міст" проти "Харківська область" дав score 76.8 — вище дефолту ua-coins.info, але це геть різні монети). 85 — емпірично підібраний поріг, що відсікає такі колізії, залишаючи тільки справжні майже-точні збіги (94-96% на реальних даних).

### Де зберігаємо (спільно для обох джерел)

Таблиця `{prefix}coin_prices` (`Coins\Prices\PriceSchema`/`PriceRepository`, `inc/Prices/`) — до migration phase 1-2 це був CPT `coin_price` з ACF-полями; той CPT видалений разом з усіма постами в phase 6 (2026-08-30), таблиця — єдине сховище цін відтоді.

| Колонка | Тип | Значення |
|---|---|---|
| `coin_id` | bigint | ID нашої монети (`coins`-пост) |
| `price_date` | date | Дата фіксації ціни (`Y-m-d`) |
| `price` | decimal(12,2) | Ціна в гривнях |
| `source` | varchar(32) | `ua-coins.info` або `coins.bank.gov.ua`, залежно від імпортера |
| `sku` | varchar(32) | Артикул товару НБУ, якщо переданий (порожній рядок інакше) |

Для `coins.bank.gov.ua` немає точної дати ціни (лише "станом на дату останньої реалізації") — імпортер підставляє дату запуску команди (`--price-date`, за замовчуванням сьогодні).

**Дедуплікація**: `UNIQUE (coin_id, source, price_date)` на рівні схеми — саме з `source` у ключі, інакше при накладенні дат від двох джерел один імпортер тихо перезаписав би ціну іншого. Запис — `INSERT ... ON DUPLICATE KEY UPDATE`, батчами; повторний запуск на тих самих даних безпечний (idempotent).

## Як віддаємо назовні

GraphQL-поле `Coin.priceHistory` (`inc/GraphQL/CoinGraphQL.php`) → `PriceRepository::forCoin()` — індексований запит по `(coin_id, price_date)`, повертає записи з обох джерел разом (поле `source` дозволяє розрізнити на фронті). Достатньо швидкий і для одиничного запиту (сторінка монети), і — на відміну від старого CPT-варіанту — для списків, якщо колись знадобиться (`PriceRepository::forCoins()`).

## Запуск

```bash
# --- ua-coins.info ---
wp uacoins import-prices --dry-run              # прев'ю без запису в БД
wp uacoins import-prices --post_id=169           # одна монета
wp uacoins import-prices                         # весь каталог coins
wp uacoins import-prices --rematch                # ігнорувати кеш матчингу
wp uacoins import-prices --min-score=70           # інший поріг схожості
wp uacoins import-prices --limit=20               # обмежити кількість монет

# --- coins.bank.gov.ua (архів) ---
wp nbuarchive import-prices --file=archive.json --dry-run
wp nbuarchive import-prices --file=archive.json
wp nbuarchive import-prices --file=archive.json --price-date=2026-08-27
wp nbuarchive import-prices --file=archive.json --min-score=90
```
